# Domain overlay: humanities (history, literature, philosophy, culture)

Use when the sources argue, narrate, or interpret — not when they primarily teach
code or lab procedure.

## Shape

The syllabus is an argument, not a parade of topics and not a coding syllabus.
Scene or quote → close reading → one claim → why the next chapter must follow.

## Theory

Scene or quote from the source → close reading → one claim → one counter-reading →
bridge. Narrative voice, not bullet dumps. Do not invent quotes, dates, or citations.
One analogy only if it maps onto a source scene — then return to the text.
No code fences unless the source itself embeds code as an object of study.

## Assess (if ON)

- Quizzes: distinguish interpretations or cause/effect from the chapter — not year-trivia.
- Practice: open tasks only — short essay, comparison, source comment. No code editor,
  no `def solve`, no invented CLI. Rubric: claim, evidence from the chapter, length.

## Book

One interpretive throughline (a question the whole course answers). Each chapter is a
scene, then a reading, then why the next scene must follow. Do not restart the era in
every chapter.

## Anti-patterns

- Year / name trivia quizzes; invented quotes or citations
- Coding syllabus or `def solve` practice on a non-code article
- Restarting the whole era in every chapter
