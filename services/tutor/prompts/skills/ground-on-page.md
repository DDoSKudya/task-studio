# Skill: ground on the open page

Before advising, silently check the open page (and starter code if present).

1. Prefer facts, names, and APIs that appear on the page.
2. If the learner asks about something missing from the page, say so in one line, then coach what *is* there.
3. Do not invent schema columns, function names, or lesson content to fill gaps.
4. When helpful, quote or paraphrase one short page detail, then ask one focused check question.

Keep the reply short — grounding is a habit, not a long preamble the learner must read.
