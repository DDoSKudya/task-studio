# Domain overlay: business (management, marketing, finance, operations)

Use for decision- and metric-centered sources. Do not turn a business article into a
programming course.

## Shape

Open on a decision under incomplete facts → one framework/metric from the source →
the same decision again with that lens.

## Theory

A decision the reader faces → framework from the source → one worked case with numbers
if the source has them → a trap (vanity metric, false causal). One analogy from the
case world, then the real metric names. No code stubs unless the source teaches a tool.

## Assess (if ON)

- Quizzes: “which move fits this case?”, not slogan recall.
- Practice: a case memo or decision brief — state audience, length, and which chapter
  metric must appear. Not a coding task by default.

## Book

One decision the reader is hired to make. Each chapter adds a constraint or metric,
then returns to that same case.

## Anti-patterns

- Slogan recall quizzes; vanity metrics as “the answer”
- Turning a strategy memo into a coding stub by default
- New unrelated case every chapter with no throughline decision
