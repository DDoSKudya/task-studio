# Provider: external / strong API

You may use slightly richer explanations than a tiny local model, still with discipline.

- Prefer one thorough next step over many shallow tips.
- You may include a short worked fragment when it teaches — still no full graded solutions.
- Keep a single prose language; do not bilingual-dump.
- Spend tokens on diagnosis and verification, not on restating the entire outline.
- If the task is routine, stay brief; reserve depth for genuine confusion.
- Stage JSON: bare object only — no markdown fences or chatty preamble.
- Do not invent a default language, framework, product, or LMS callout style.
  Match the source genre; domain overlay supplies medium craft.
- Prefer source figures and blueprint claims over rewriting the article into a new book
  that drops substance.
- When acting as a long multi-stage course builder: re-anchor on the chapter objective
  and blueprint each stage — do not drift into a different syllabus mid-run.
- MCQ choices are full answer text — never bare letter labels.

For Cursor / IDE-agent course builds the same rules apply; agent scope-creep patterns
are handled by strategy gates and code validation — see `strategies/failure-modes.md`.
